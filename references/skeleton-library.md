# 骨架库（9 种，全部来自范文实例）

选卡时用。每张卡标注适用位置。可以组合，但一张卡内节点顺序服从卡型。

## 骨架 1：设计权衡的完整链条
- **用于**：方法章的模块说明。
- **结构**：收益A → 收益B → 但代价 → 补偿 → 净结果
- **要点**：代价必须自己先说，不能让审稿人替你发现。缺代价像在吹，缺补偿像没想清楚。

## 骨架 2：问题—对策—分工—结算
- **用于**：摘要、引言末段、结论。
- **结构**：约束1 ∧ 约束2 → 为此 → 合流 → 拆开职责 → 成本换收益
- **要点**：摘要不给具体数字，只给交易结构。

## 骨架 3：两条路线互相补充
- **用于**：引言的相关工作段。
- **结构**：解法A解决gap1 → 然而撞上gap2 → 转轨 → 解法B解决gap2 → 然而又撞回gap1 → 前后接上
- **要点**：两条路互相证伪，读者被逼到唯一出口，下一段的"融合"就是逻辑必然。

## 骨架 4：先扬后抑
- **用于**：引言第一段。
- **结构**：任务定义 → 价值传导 → 先承认现状很强 → 然而存在 N 个关键局限 → 逐条展开
- **要点**：数量要预告（"两个"），读者会核对；两条局限必须正交，且与后文方法组件一一对应。

## 骨架 5：让步—转折—立论
- **用于**：结果分析段。
- **结构**：承认普遍规律 → 指出本文的例外 → 例外为什么重要
- **要点**：先建中立框架再说例外。直接说"我们最好"读者无从判断。

## 骨架 6：读数—归因—角色
- **用于**：实验读数段。
- **结构**：指向表/图 → 读最分裂或最关键的一行 → 归因给机制 → 由机制推出该组件的角色
- **要点**：读数顺序服从论证，不服从表格顺序。从最分裂的那行读起，矛盾正是论证入口。

## 骨架 7：立标尺—打破标尺
- **用于**：主结果段。
- **结构**：挑两个同类不同规模模型 → 抽出"规模↑性能↑"规律 → 用本文方法打破它
- **要点**：先立尺，反超才有冲击力。没有尺，数字只是数字。

## 骨架 8：承认—假设—验证—转出
- **用于**：异常读数、局限说明。
- **结构**：主动点出不利读数 → 用"可能"给机制假设 → 用已有图表做零成本验证 → 转成未来工作
- **要点**：不回避不淡化，把负面结果变成研究深度的证据。

## 骨架 9：限定的完整交代
- **用于**：方法章边界、结论展望。
- **结构**：承认边界 → 给可行的改造路径（证明不是硬伤）→ 明确划界
- **要点**：从只说"本文未考虑"，改成"未考虑 + 可以怎么补 + 边界在哪"。

## 长句生长机制（填充时配合骨架用）

1. **因果前置**：先"由于 X"再给结果，读者读到数字时已经知道往哪解释。
2. **成对义务**：改一个部件必须交代对称件或逆操作，信息成对出现。
3. **数量校验**：先给总数，再给组成，最后一句校验总数。校验句把结构定义变成后文消融的自变量。

反例：往句尾堆修饰语。句子变长但信息没有增加，这是 AI 长句和人写长句的分界线。

## 数字分工

| 位置 | 规则 |
|---|---|
| 方法与设置段 | 参数名在前、数值在后；区间优先于单值 |
| 结果读数段 | 对比对在前 → 定性词 → 括号补 delta；正文不堆绝对值 |
| 摘要与结论 | 零具体数字，或绝对读数 + 相对倍数 |

核心：表给数，正文给判断，摘要给交易结构。
