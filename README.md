# zh-skeleton-writing

中文论文写作技能，装在 Claude Code、ZCode 等支持 SKILL.md 的 agent 上用。它把"先搭论证骨架、再填充成句"的写作流程做成工作区里的强制步骤，用来消除中文论文里的 AI 味。

## 它解决什么问题

LLM 写中文论文，词是对的，句子是通的，但整段读起来像从英文翻译过来的：先给结论再垫证据，每组数据后面缀一句"这表明"，展开信息塞进括号和冒号。这些症状的根源不在词汇，在论证结构：模型跳过了人写作前的规划，直接从上文采样下一个词。

这个技能的规则不是凭感觉定的。依据是三篇《声学学报》论文的逐句标注（41 段 170 句），每条规则都能回到语料里的数字，例如：

- 范文段首几乎全是叙事性起点（背景、条件、指表、承接），结论型段首 41 段里只有 1 处；结论标记 27 次出现在句中句末，8 次在句首。先亮主张再垫证据，是英文段落写法。
- 范文 11,902 字里全角冒号 0 次；口语动词（做、跑、搞、弄、给出）0 次。
- 长句的长度由逻辑槽位数量决定：范文的打包率是每句 1.2 到 4 个逻辑节点，从没有把一个节点拆进两个句子。

## 怎么工作

接到写作任务后，模型在一个临时工作区里按七步走：

1. 材料进场：任务、数据表、数字白名单、红线落成文件
2. 断言清单：一条断言对应一段
3. 四层骨架卡：节论证链 / 段落 / 逻辑节点 / 打包成句
4. 卡片过审：预期问题是否具体、背景信息是否有独立节点、结算句能否成为下一段的前提、结论节点是否被排到了段首
5. 隔离填充：写手只看当前这一张卡
6. 机械门禁：三个 Python 脚本检查
7. 脱架定稿：不看卡片通读一遍，只顺衔接不改信息

门禁脚本查四类硬性问题，不通过就退回对应的层重做：数字是否全部来自白名单、自造词与英文直译句式、解释性括号、冒号展开和口语动词。

## 安装

把本目录复制到 skills 目录（Claude Code 是 `~/.claude/skills/`，ZCode 是 `~/.zcode/skills/`），重启会话。门禁脚本需要 Python 3，无其他依赖。

## 使用

对话里说"用 zh-skeleton-writing 写 X 节"，或者给 subagent 派任务时把 SKILL.md 的路径贴进 prompt。写作材料（数据表、数字白名单）按 SKILL.md 第 1 步的格式提供。

## 目录

```
SKILL.md       主流程（七步）与规则索引
references/    四份细则：卡片规范、骨架库、风格规则、自检清单
scripts/       三个门禁脚本：数字白名单、禁用词、括号边界
evals/         测试用例
```

## 测试情况

在 GLM-5.3、GLM-5.3-Flash、deepseek-flash 三个模型上做过功能测试（同一写作任务，含无技能对照组）。带技能的运行全部通过机械门禁和结构审查；无技能的对照会漏出解释性括号、冒号展开、口语动词和段首裸主张。测试记录见规则文档中的迭代说明。

## 边界

- 方法依据的是三篇语音方向的《声学学报》论文，其他学科未验证。
- 这是写作规范，不是 AI 检测器，不要用它判断一段文字是否由 AI 写成。
- 门禁脚本是启发式的，数字白名单需要每个任务单独提供。
